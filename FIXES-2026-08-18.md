# Satoshi's Council — fixes applied 2026-08-18

Root-cause + fixes for "it calls worse than my other bots." Verified against the
live `council.db` (2,027 window rows, 63k signal rows) plus a 5-agent diagnostic.
Two things were true at once: the accuracy number was partly lying, AND the
council underneath was inert. Both are now addressed.

## Fixed & verified

1. **Permanent veto removed** — `backend/services/round_table.py`
   The ORACLE "derivatives feed dark" check was a HARD veto that fired on every
   decision (3,543 / 3,543) because the CoinGlass key is plan-walled
   (`need Startup+ for 30m/1h`). Moved from `protective_vetoes` to
   `protective_cautions`: a missing crowding feed now caps size, not the desk.

2. **Council un-starved — the big one** — `backend/services/round_table.py`
   `_side()` only recognized `UP`/`DOWN`/`UP_HOLD`/`DOWN_HOLD`, but the seats emit
   the scalp engine's language `LONG_UP`/`LONG_DOWN`. So EVERY momentum/odds/
   strike/spotlag seat looked like "no side" and its leader could never lean —
   alignment was mathematically stuck at 1 of 4. Fixed `_side` to map `LONG_*`
   (as `calibration._correct` already did). Result on 3,000 real windows:
   - ARES now leans 86% (was 0%), VITALIK 20%, RAIJIN 23%, ORACLE 0% (process seat).
   - Alignment reaches 3-of-4 on ~10.6% of windows (was 0%).
   - Satoshi commits ~10.6% (disciplined), stands down 89.4%, **0 calls against
     its own alignment**.
   - `MIN_ALIGNMENT` stays 3 — discipline preserved, no bar-lowering needed.
   - Under the dark feed it commits as size-capped HOLD; a healthy feed unlocks
     full-size UP/DOWN.

3. **Accuracy metric stops lying** — `backend/main.py` (`_committed_finish_rows`)
   `/api/calibration`, `/api/backtest`, `/api/public/proof` re-graded rows the
   settler left ungraded: chalk auto-counted as WINS, path legs fabricated as
   LOSSES. Now they grade only genuinely committed calls (`correct in 0/1`). The
   fake "overconfident 13pts, decay 64%→52%" (1,139 rows) becomes an honest ~83%
   on ~30 real calls, correctly flagged **thin**.

4. **Honest CALL ACCURACY metric works** — `backend/storage/db.py`
   `spot_at_call`/`spot_at_close` were dead (0/2,027). Added an `entry_price`
   fallback (the BTC spot) so the chalk-immune MOVE grade populates going forward.

5. **Badge redesigned** — `frontend/static/{index.html,style.css,roundtable.js}`
   CALL ACCURACY (chalk-immune) is the headline; realized P&L per window is the
   dim secondary; frame color follows CALL ACCURACY.

6. **Council wired into the trade engine (default OFF)** — `backend/services/
   council.py`, `round_table.py` (`council_final`), `config.py`
   (`COUNCIL_GATE_MODE`). The decision path now computes Satoshi's Round Table
   verdict from the same signals and attaches it to every decision. New setting
   `COUNCIL_GATE_MODE`:
   - `off` (default) — advisory only; the council decision is attached for
     measurement but trades are UNCHANGED. Ship-safe: no surprise P&L change.
   - `hard` — on a council stand-down (no confluence), force WAIT and drop NEW
     directional path legs (existing legs still cut/flip). This is the switch
     that makes the council's discipline actually gate what gets graded.
   Verified: off = byte-identical trades; hard = opens suppressed only when the
   council sits; `council_final` reproduces production's `min_alignment=3`; the
   whole block is wrapped so it can never break a live decision. All 13 tests pass.

   **Recommended rollout:** run with `COUNCIL_GATE_MODE=off` first and watch the
   Round Table's finish hit-rate (fix #7) + whether its confluence windows
   outperform, THEN flip to `hard`. Set it in your `.env`.

7. **Council is now finish-graded** — `backend/services/process_log.py`
   (`settle_finish`), `council.py` (`_grade_council_from_results`). When a window
   settles on the official Kalshi finish, the Round Table's OWN decision is now
   scored: a directional call → correct = (its side matched the finish); a
   stand-down records the finish but stays ungraded (sitting is never a miss).
   This gives the council a real finish hit-rate — independent of the scalp
   engine — surfaced by the existing `/api/process/metrics` (`hit_rate_pct`) and
   the patience metric. Verified: grading is exact and idempotent; 116/117 real
   process-log rows matched their finished tickers; the patience metric already
   lights up (of resolved stand-downs, 42 dodged a loss). The hit-rate itself
   fills in once the un-starved council starts making directional calls (post
   restart). This is how you PROVE the council adds edge before flipping the
   `hard` gate.

## Desk reframe — readability + honest learning (2026-08-18, later)

8. **THE CALL marker** — `frontend/static/{index.html,style.css,roundtable.js}`
   One unmistakable banner at the top of the table: colour = side (green up /
   red down / amber small / slate sit), the word = the exact action
   (Accumulate / Reduce / Maintain / Stand down). Can't be confused with the
   seat lights.

9. **Win/loss scoreboard off the desk face** — a real desk doesn't show
   "hits/misses". Hidden the header accuracy badge, the right/wrong hit-rate
   card, the L20/L50 roll, and the lifetime log; the left panel is now
   **DISCIPLINE** (process, patience, stand-downs). A quiet "MODEL · LEARNING"
   chip replaces the badge. Detailed numbers still live in the Calibration /
   Backtest research tabs.

10. **Bots now learn on the right signal** — `backend/services/council.py`,
    `backend/learning/adaptive.py`. BTC 15m finish_match/finish_miss rows now
    fall through to `learn_from_settled` (they were skipped — BTC seats only
    ever learned on path P&L, never on direction). AND the learner no longer
    drops `LONG_*`/`HOLD` votes (it required exactly UP/DOWN, silently skipping
    momentum/odds/strike/spotlag — the main directional voters). Now the seats
    learn whether they called the move (up/down) before it happened — the goal —
    silently on the backend. Verified: momentum(LONG_UP)/odds grade correct vs an
    UP finish, strike(LONG_DOWN) wrong; 34 real BTC finish rows now train; all
    tests pass.

11. **Floor split** — `frontend/static/{index.html,style.css,roundtable.js}`
    In floor mode: left = "what the coin is doing" (big price, % change, live
    line chart); top-right = "what the council says" (Satoshi's call, the four
    leaders with one clear ▲/▼/■ chip each, a plain-English verdict, and "calls
    ahead of price"); bottom-right = **the bots** — the round-table canvas tucks
    into that corner (framed) so you still see the people on the floor. Reads
    left→right for a newcomer. Stacks on narrow screens; wrapped so it can never
    break a live decision. Verified: price left / council top-right / bots
    bottom-right, chart draws, all data populates.

12. **Floor calls now agree with the leaders** — the floor's Satoshi call was
    read from the scalp engine (`liveCallCard`) while the leaders came from the
    council board — two different systems, so they contradicted. Added
    `councilCallRead()` and pointed BOTH the call marker and the floor split at
    the council board, so the call always matches the seats. Also: every leader
    row now carries a state colour band (green up / red down / slate sit), so all
    four read clearly — not only the ones leaning.

13. **"School" tab → "Dojo" launcher** — `frontend/static/{index.html,roundtable.js}`
    The School tab is now **Dojo**. Clicking it opens the standalone **Candle Dojo**
    app (a separate Vite/React/TanStack-Start app with its own server + database) in
    a new browser tab. Address is `window.DOJO_URL` (index.html, default
    `http://localhost:8080`) — run the dojo (`npm install && npm run dev` in the
    candle-dojo folder) or point it at your deployed dojo. `setMode("dojo")` calls
    `openDojo()` instead of switching a desk view. Also clarified a few cryptic tab
    labels: **15M → 15-min**, **Brain → Huddle**, **WIRE → Changes**.

## Report-card follow-ups (2026-08-18, after the 5-agent review)

An independent 5-agent review scored the desk (overall 4/10: looks 6, UX 4,
works 7, edge 2, code-health 4). Acted on the safe, high-value findings:

14. **API-crash gap closed (works)** — `round_table.py` `build_round_table` caught
    only `ImportError` on the regime/HUD calls, so a *runtime* error there could
    500 the `/api/round-table` endpoints. Now `except Exception` → degrades to a
    neutral posture / empty risk panel, matching `council_final`.

15. **Critical path now under test (works + code-health)** — new
    `backend/tests/test_council_core.py`: 14 behavioural tests covering `_side`
    (LONG_* mapping), `satoshi_call` (confluence / veto / dark-feed discipline),
    `council_final` (garbage inputs → Stand down, never raises),
    `_committed_finish_rows`, `settle_finish` (grade / miss / stand-down / idempotent),
    and `learn_from_settled` (LONG_* graded). 13 → **27 tests, all green**.

16. **"Feed dark" is now honest, not "broken" (UX)** — when CoinGlass is
    plan-walled, the CROWDING panel shows one clear line ("Derivatives feed dark —
    CoinGlass plan wall … not broken, intentionally dark") instead of a column of
    ambiguous "warming up / no print" placeholders.

17. **Colour tokens restored (looks)** — the newer floor-split / call-marker CSS
    hardcoded `#39ff14/#ff2d55/#f0c14a`; swapped every solid occurrence to
    `var(--jade/--blood/--gold)` sheet-wide (verified `--jade` → rgb(57,255,20)),
    so the theme has one source of truth for its colours again.

**Not done, deliberately:** the trade engine was left untouched — the negative-EV
staking finding runs through the exploration-lock path and I don't yet fully
understand the ev_cents discrepancy; changing the live trade path on an
incomplete read, right before a push, is the wrong move. The edge score is a
"needs more honest data + trade-path work we verify live together" item, not a
quick patch.
